# Test Cases — Checklist

## ก่อนทดสอบ

- [ ] Apache + MySQL ใน XAMPP ทำงาน
- [ ] Import SQL และ copy `config/app-config.php` แล้ว
- [ ] `?route=health` คืน `status: ok`
- [ ] Flutter SDK ตั้ง PATH และสร้าง Android/Web platform แล้ว
- [ ] กำหนด `API_BASE_URL` ถูกเครื่อง/พอร์ต

## Process 1 — Auth

- [ ] สมัครสมาชิกใหม่ → เข้าหน้าหลักทันที
- [ ] สมัครด้วยอีเมลเดิม → แจ้งอีเมลซ้ำ
- [ ] รหัสผ่านผิด → ไม่อนุญาต
- [ ] ปิด/เปิดแอปใหม่ → จดจำ token
- [ ] Logout → กลับหน้าเข้าสู่ระบบ
- [ ] User A ไม่สามารถดู/แก้ไขรายการของ User B ได้

## Process 2–5 — Finance & AI

- [ ] เพิ่มรายรับ 1,500 บาท → Dashboard เพิ่มรายรับ
- [ ] เพิ่มรายจ่าย 250 บาท → Dashboard เพิ่มรายจ่าย
- [ ] แก้ไข/ลบรายจ่าย → Dashboard ปรับยอด
- [ ] D/M/Y เปลี่ยนยอดถูกต้องตามช่วงเวลา
- [ ] อัปโหลดบิล JPEG/PNG/WebP → AI คืนร้าน/วันที่/ยอดรวม
- [ ] ตรวจและแก้ไขผล AI → บันทึกรายจ่าย + เปิดดูรูปได้
- [ ] อัปโหลดรูปเดิมซ้ำ → สแกน AI ใหม่ได้และสร้าง receipt_id ใหม่ โดยไม่แก้ข้อมูลผลสแกนเดิม
- [ ] ยืนยันบันทึก receipt_id เดิมซ้ำ → ไม่สร้างรายจ่ายซ้ำจากผลสแกนเดียวกัน
- [ ] ไม่มี AI API Key → แจ้งให้ตั้งค่า

## Process 6 — Subscription

- [ ] เพิ่ม YouTube Premium จ่ายวันที่ 16 → Calendar มีรูปบริการวันที่ 16
- [ ] เพิ่มบริการรายปี → แสดงเฉพาะเดือนครบรอบ
- [ ] วันที่ 31 เดือนกุมภาพันธ์ → แสดงวันสุดท้ายของเดือน
- [ ] กดชำระ → สถานะจ่ายแล้ว + สร้างรายจ่าย
- [ ] กดชำระซ้ำ → ไม่สร้างรายจ่ายซ้ำ
- [ ] จ่ายแล้วเปลี่ยนวันตัดรอบภายในเดือนเดิม → ยังขึ้นจ่ายแล้วและจ่ายซ้ำไม่ได้
- [ ] เปลี่ยนยอดหลังจ่าย → ประวัติและยอด event ที่จ่ายแล้วไม่เปลี่ยน
- [ ] รายปีจ่ายแล้วเปลี่ยนเดือนเริ่มต้นภายในปีเดิม → จ่ายซ้ำในปีเดิมไม่ได้
- [ ] รอบเดือน/ปีถัดไป → ชำระได้ตามปกติ
- [ ] ยกเลิกบริการ → ไม่แสดงรอบใหม่, ประวัติรายจ่ายเก่ายังอยู่

## Process 7 — Budget

- [ ] ตั้งงบรวม 5,000 บาทสำหรับเดือนปัจจุบัน
- [ ] ตั้งงบหมวดอาหาร 2,000 บาท
- [ ] เพิ่มรายจ่ายหมวดอาหาร 1,600 บาท → 80% มีข้อความเตือน
- [ ] เพิ่มอีก 400 บาท → 100% มีข้อความเตือน
- [ ] แก้ไขวงเงินเดิมผ่านเลือกหมวดอีกครั้ง → บันทึกทับ ไม่สร้างงบซ้ำ
- [ ] เปลี่ยนเดือน → งบและยอดใช้งบถูกกรองตามเดือน

## Process 8 — ผ่อนสินค้า

- [ ] สินค้า 24,000 ดาวน์ 4,000 ผ่อน 10 งวด → งวดละ 2,000
- [ ] ชำระงวดแรก → คงเหลือ 18,000 และรายจ่ายเพิ่มครั้งเดียว
- [ ] ชำระงวดเดิมซ้ำ → 409 และรายจ่ายไม่เพิ่ม
- [ ] แนบหลักฐาน → เปิดดูได้เฉพาะบัญชีเจ้าของ
- [ ] ยกเลิกการบันทึก → คืนยอดคงเหลือและนำรายจ่าย/หลักฐานของงวดนั้นออก
- [ ] วันที่ 31 ผ่านกุมภาพันธ์ → ใช้วันสุดท้ายแล้วกลับเป็นวันที่ 31 ในมีนาคม
- [ ] หารยอดไม่ลงตัว → ปรับสตางค์งวดสุดท้ายและยอดรวมตรง
- [ ] เชื่อมเงินดาวน์กับรายจ่ายเดิม → ไม่สร้างรายจ่ายซ้ำ
- [ ] ชำระครบ → ย้ายไปประวัติผ่อนครบแล้ว

## Validation และชุดติดตั้ง

- [ ] ยอด `0.004`, `1.234`, `0`, ติดลบ และเกินเพดาน → แอป/Backend ปฏิเสธ
- [ ] ยอด `0.01`, `1.20`, `9999999999.99` → บันทึกได้ครบสตางค์
- [ ] sync Backend → มี `storage/receipts` และ `.htaccess` ครบ โดย config/รูปเดิมยังอยู่
- [ ] เปิด config, storage, SQL และ src ตรงผ่าน HTTP → 403
- [ ] APK release มี permission INTERNET และ local HTTP สำหรับ XAMPP
- [ ] URL ในคู่มือตรงกับ API ที่ใช้งานจริง

## Automated checks

ตรวจชุดไฟล์สำหรับ GitHub วันที่ 9 พฤศจิกายน 2026 หลังนำไฟล์ที่ไม่จำเป็นออก: Flutter tests ผ่าน 24 รายการ; analyzer มี info เดิม 25 จุด ไม่มี error/warning; PHP syntax ผ่าน 17 ไฟล์; `installment_schedule_test.php` และ `backend_package_test.ps1` ผ่าน; Android debug APK build ผ่าน ตรวจ SHA-256 ยืนยันว่าโค้ดแอป Backend ฟอนต์ ชุดทดสอบ และ dependency lockfile ไม่เปลี่ยนจากก่อนจัดไฟล์ ลิงก์เอกสารภายในครบ ชุดทดสอบ API ที่ใช้ฐานข้อมูลและการเรียก AI จริงไม่ได้รันใหม่ในรอบจัดไฟล์นี้

ตรวจวันที่ 13 ตุลาคม 2026: Flutter tests ผ่าน 24 รายการ; analyzer ไม่มี error/warning แต่ยังมีข้อเสนอแนะระดับ info เดิม 25 จุด ชุดทดสอบ PHP ทั้ง 5 สคริปต์ผ่าน และชุดติดตั้ง Backend ผ่านโดยไม่ทับ config/รูปเดิม:

- `mobile/test/installments_test.dart`: การคำนวณตารางและสตางค์
- `mobile/test/money_validation_test.dart`: จำนวนเงินและ validation ของฟอร์มรายรับ/รายจ่าย
- `mobile/test/installment_flow_test.dart`: เพิ่มสินค้า ชำระ ป้องกันกดซ้ำ ผ่อนครบ ยกเลิก และ retry
- `tests/subscription_amount_api_test.php`: จ่ายซ้ำหลังแก้วัน/เดือน รอบถัดไป เงินผิดรูปแบบ และการแพ็ก Backend
- `tests/installment_schedule_test.php`, `tests/installment_api_test.php`: ตารางงวด API หลักฐาน และการเชื่อมรายจ่าย

- `tests/profile_api_test.php`: โปรไฟล์ รูป และรหัสผ่านแบบเดิม
- `tests/backend_package_test.ps1`: ทดลอง sync ลงโฟลเดอร์ชั่วคราว ตรวจไฟล์ป้องกัน/โฟลเดอร์รูป/migration ครบ และรักษา config/รูปที่มีอยู่

คำสั่งและตำแหน่ง Backend อยู่ใน [README](../README.md) บัญชีทดสอบชั่วคราวล้างออกหลังจบ

Android release build ผ่านแล้ว (`app-release.apk` 51.9 MB) และตรวจ manifest ที่แพ็กแล้วว่ามี `android.permission.INTERNET` กับ `usesCleartextTraffic=true` ใช้ URL สำหรับ emulator: `http://10.0.2.2/mobileapp_backend/backend/api/index.php` การติดตั้งใช้งานบนโทรศัพท์จริงต้อง build ใหม่ด้วย IP ของเครื่องที่รัน XAMPP

## Known limitations

- แค่แจ้งเตือนในหน้าแอป ไม่มี push notifications
- ปุ่มบันทึกชำระ Subscription ไม่ตัดเงินจริง
- มีการทดสอบอัตโนมัติและ build Android แล้ว; ทดสอบสแกนบิลกับ AI จริงเพิ่มเติมวันที่ 11 พฤศจิกายนตามบันทึกด้านล่าง และยังไม่ได้ตรวจ build เว็บในรอบนี้

## ภาพการทำงานสำหรับ GitHub — 10 พฤศจิกายน 2026

ดู [สารบัญภาพทั้ง 8 Process](../screenshotforgithub/README.md) ภาพ 43 ภาพมาจาก Android emulator โดยใช้บัญชีและข้อมูลสาธิต ทดสอบเพิ่มรายรับ ลบรายการสาธิต เพิ่มรายจ่าย บันทึกชำระ Subscription ตั้งงบ สร้างรายการผ่อนตามสัญญา ชำระพร้อมไฟล์แนบ เปิดดูไฟล์แนบ และยกเลิกการบันทึกงวดผ่านแอปจริง โค้ดแอปและ Backend ไม่ได้แก้ไขในรอบแคปภาพ

สแกน AI ได้ถึงการเลือกรูปและส่งคำขอ Backend แต่ชื่อเซิร์ฟเวอร์ของผู้ให้บริการที่ตั้งค่าในเครื่องแปลงเป็น IP ไม่ได้ จึงยังไม่ได้แคปผลอ่านบิลสำเร็จและหน้าที่ยืนยันรายจ่ายจากผล AI ในรอบนี้ ภาพข้อความผิดพลาดรวมอยู่ในสารบัญ

## สแกนบิลจริงเพิ่มเติม — 11 พฤศจิกายน 2026

ผู้ให้บริการ AI กลับมาเชื่อมต่อได้ ทดสอบผ่านแอป Android จริงด้วยบิล JPEG ใหม่สองใบจาก [ExpressExpense Sample Receipt Dataset](sample-receipts/README.md):

- Bar Ristorante San Montano: อ่านวันที่ `2018-08-28` ยอดรวม `34.00` หมวดอาหาร และรายการสินค้าหกรายการได้ เปิดฟอร์มตรวจสอบสำเร็จ ยังไม่ได้กดบันทึกใบนี้

บิลต้นฉบับใช้ USD และ EUR แอปแสดงจำนวนเงินด้วยรูปแบบบาทโดยไม่มีการแปลงอัตราแลกเปลี่ยน ใช้เป็นข้อมูลสาธิตเท่านั้น ภาพชุดล่าสุดรวม 53 ภาพครอบคลุม 8 Process ไม่มีการแก้โค้ดแอปหรือ Backend ในรอบนี้ ไม่ได้รันชุดทดสอบทั้งหมดซ้ำเพราะเพิ่มเฉพาะเอกสารและภาพ
